## Reading the map

| Mark | Meaning |
| --- | --- |
| S | Software exists in the reviewed source for the stated bounded behavior. This does not establish successful execution or complete acceptance evidence. |
| I | A known final software integration is still pending in this review's committed base. It must be integrated before calling software delivery complete. |
| D | Deployment, credentials, configured provider access, actual wallet authorization or authoritative onchain/provider outcome is still required. |
| O | A human operating decision, real cost observation, support staffing, external party, demonstration or review is required. Software cannot create that evidence. |
| C | Conditional capability remains deliberately disabled; its enablement condition has not been met. |
| F | Explicitly deferred from this crypto release; not completed and not counted among the 146 active checks. |
| M | A genuinely missing in-scope software implementation, if found. |

Combined marks describe separate dimensions. For example, S + D means source exists but a configured live outcome is unproved. Checkboxes in the original checklists still mean demonstrated acceptance, not S. An unchecked item may therefore have substantial implemented software. ID ranges below include every intervening numbered ID.
