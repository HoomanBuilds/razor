## Upgrade and recovery authority

Treasury, clearing, billing and credit retain one operator-controlled full-access key each. The exact public keys are pinned per account in the ignored local environment and verified against the operator secure keychain and final chain state. Company signing keys and limits are separate and cannot prevent an operator from replacing contract code. Future replacements require compatible state or a specifically reviewed migration, plus updated reviewed code pins. Never run `new` over populated state.

These upgrade keys were generated separately for the child accounts. The owner wallet recovery phrase alone does not restore them. Back up the deployment keychain securely for future upgrades; no private signing keys are committed or copied into application configuration.

Evidence alone has zero access keys. Its key was retired only after code verification and return of spare native funds. It is immutable and cannot be upgraded or deleted through a deployment key. Its recording callers pay gas; do not send it operating topups.
